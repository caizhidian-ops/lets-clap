# 本地拍手输入

游戏音乐室顶部的「开启拍手」授权麦克风；拍手、空格和按钮共用当前回合的 `run.ingest()`，识别时间点相对于同一个 AudioContext 的 `startAt`。不使用语音转写或大模型，不上传或保存麦克风音频，只保留拍点和输入来源。结尾歌曲使用这些拍点合成鼓声，并非原始拍手录音。

`clap-input.js` 使用 getUserMedia → AudioWorklet → 静音输出。回声消除开启，降噪与自动增益关闭（以设备实际 settings 为准）。不将麦克风声音回放到扬声器。检测逻辑在 `clap-detector.js`：约 5ms 能量窗口、1800Hz 高通、能量突增和高频占比、环境噪声自适应阈值、启动 0.8 秒校准、180ms 重复触发抑制。输入时间取音频线程采样帧，避免按主线程收到消息的时刻打分。

麦克风权限拒绝、设备中断和模块失败可重试；回合完成、退出、页面离开时关闭采集。当前回合内不能切换输入模式，但开启拍手后空格和按钮仍可起跳。混合使用时结果标为 `mixed_mic_tap`；只用麦克风为 `microphone_clap`，原有输入为 `tap_demo`。开启拍手时关闭高频判定音效，减少游戏自身声音误触发。

## 验证入口

- `http://127.0.0.1:5173/clap-test.html`：真实麦克风电平、候选拍手数量、音频时间与处理/消息延迟；支持本机读取音频文件和无鼓伴奏误触发检查。文件不上传。
- 使用 README 指定的 bundled Node 执行 `node --test`。
- HTTPS 或本机回环地址。手机访问局域网 HTTP 不能直接当作安全上下文。

## 2026-10-11 证据与边界

- 合成宽带突发样本在 44.1/48kHz 下逐次检出，起点误差不超过 5ms；静音、低频提示音和持续低幅噪声无触发。
- 用户提供的 30 秒立体声无鼓伴奏：直接 PCM 检测及浏览器解码后的检测均为 0 次误触发。此结论只覆盖该音频文件，并非扬声器经空气回录测试。
- Chrome 真麦克风实际采样率 48kHz、回声消除 true、设备设置报告采集延迟 10ms。现场测试页记录 14 个候选事件，处理与消息延迟约 5–15ms。用户反馈「好像还不错」，未提供实际拍手总数，不能计算准确率/召回率。
- 游戏内实际开启麦克风成功，回合中显示拍手输入，并在开启拍手时操作空格键；结束画面记录 7 次拍手、跳准 9/16，麦克风已关闭。音频时间戳与按键共用判定的合成集成测试通过；总计 30 项 Node 测试通过。

处理/消息延迟不包含声学传播、设备采集、系统缓存、输出或屏幕刷新，不能据此宣称端到端 5ms。敲桌子、爆破音、其他尖锐瞬态可能误触发；戴耳机并在真实房间测试轻拍/远拍/说话/敲击/背景音乐后，再调灵敏度。此版本是无模型的突发检测器，未获得有标注真人样本上的准确率证明。
