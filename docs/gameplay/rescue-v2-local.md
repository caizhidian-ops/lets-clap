# 风车救援 v2：本地交互与 3D 场景

2026-10-11。保留并行开发的对话流程与毛绒 SVG，改动集中在 public/game/。

## 操作修复

原来准备阶段拍一下 disabled；正式阶段只有命中 ±180ms 才动，未命中没有解释。
现在圆形按钮在准备阶段也能开始救援；四拍预备时明确显示“听准备拍”；每次正式输入都有按钮缩放和浮动文字，命中才给逃生力量。目标高亮只在有效窗口出现，并提前填充提示接近。结束按钮显示“本轮结束”。

## 紧张感

旋风环、快速风粒、随回合增强的风车速度与轻微镜头震动；剩余拍数、后段狂风提示。宠物拍准跃起、持续后滑，结局为进屋或保护泡泡。减少动态偏好下关闭晃动和跳跃动画。未更改音乐时长、命中窗口、成功比例，也没有让多拍加力量。

## 场景

Three.js 本地依赖，沿用已安装版本和 MIT LICENSE；不依赖 CDN。立体草地岛、弯曲踏石路、树林、花朵、风车和暖光小屋，有灯光、软阴影与雾。优先加载两份 Tripo GLB；失败保留基础几何场景与原 SVG 回退。

生成脚本 scripts/tripo-rescue.py 从用户既有私密 key 文件读取凭据。单资产只提交一次，先写 intent 后提交，未知结果不重试。原始任务响应/签名 URL 只写入被忽略的 .asset-jobs/，GLB 与可公开的任务 ID、prompt、SHA-256 来源写入 public/assets/rescue/。依据 https://developers.tripo3d.ai/en/docs/generation-text-to-model/standard 。生成模型整体跳跃/位移，尚无骨骼走路动画。

## 节奏边界

当前入口仍是另一流程提供的 moodStyles 测试速度，四分音符八拍。不是经审核的《大风车》节奏与伴奏。正式计划可通过 bpm/onsets/planId 输入到 escape-scene；onsets 为正式录制开始后的秒数，包含八分音符时提示额外拍点。真实麦克风检测、曲谱数据与歌曲伴奏须由相应模块接入，不用点击记录冒充真人音频。

## 并行边界

未重写 flow.js/flow-model.js，不把并行修改打包提交。纯规则仍由 escape-engine.js 负责，视觉由 escape-world.js 负责，UI 与生命周期由 escape-scene.js 负责。

## 最终生成与验证

Tripo 怪物与风车均 success，各 20 credits，总计 40。GLB 分别约 2.62MB / 3.17MB，均有嵌入纹理。浏览器确认 assets=monster,windmill，真实模型出现在立体场景；手机 390px 无横向溢出。圆形入口可启动，未命中立即解释，八拍实际点击可成功，12 项 Node 测试通过。模型暂无骨骼，宠物做整体跳跃/位移；生成风车为静态整体模型，叶片独立绑定待做。未验证麦克风、千问或正式歌曲。
